# 50 Startups 專案：CRISP-DM 分析文件

## 專案摘要

本專案以 50 Startups 資料集預測公司獲利，核心工作包含五種迴歸演算法比較、每個模型的 `K=1～5` 特徵子集合分析，以及互動式結果展示。流程依照 CRISP-DM 六個階段執行，確保商業問題、資料處理、模型建立、評估與部署彼此一致。

## 1. Business Understanding：商業理解

### 問題定義

新創公司希望了解研發、行政、行銷與所在地是否能有效解釋及預測獲利，並在預測表現與模型簡潔度之間取得平衡。

### 專案目標

- 建立可預測 `Profit` 的迴歸模型。
- 公平比較五種迴歸演算法。
- 讓使用者查看不同特徵數量對模型表現的影響。
- 找出每個 K 值下表現較佳的特徵組合。
- 透過互動式網站清楚呈現指標、係數、預測與殘差。

### 成功指標

- 主要指標：測試集 RMSE，越低越好。
- 輔助指標：MAE、R²、Adjusted R²、F-statistic 與殘差分布。
- 可用性指標：切換演算法或 K 值時，所有相關數據與圖表需同步更新。

### 產出

- 可重現的 Python 分析程式。
- 五模型比較結果。
- `K=1～5` 特徵分析結果。
- 繁體中文互動式儀表板。
- JSON 與 PNG 靜態產出。

## 2. Data Understanding：資料理解

### 資料概況

| 項目 | 內容 |
|---|---|
| 資料筆數 | 50 |
| 輸入欄位 | 4 個原始欄位 |
| 目標欄位 | `Profit` |
| 類別欄位 | `State` |
| 數值欄位 | `R&D Spend`、`Administration`、`Marketing Spend` |

### 欄位意義

| 欄位 | 類型 | 說明 |
|---|---|---|
| `R&D Spend` | 數值 | 研發支出 |
| `Administration` | 數值 | 行政支出 |
| `Marketing Spend` | 數值 | 行銷支出 |
| `State` | 類別 | 公司所在州別 |
| `Profit` | 數值 | 公司獲利，也是預測目標 |

### 初步理解

- 資料量小，任何單次訓練／測試切分都可能造成評估波動。
- `State` 必須轉換為模型可使用的數值欄位。
- 支出欄位尺度不同，正則化模型與 Huber 模型需要標準化。
- 研發與行銷支出預期與獲利相關，但仍需透過模型及測試資料驗證。

## 3. Data Preparation：資料準備

### 目標與特徵

- `X`：除 `Profit` 外的所有欄位。
- `y`：`Profit`。

### 處理步驟

1. 使用 `train_test_split` 切分 80% 訓練集與 20% 測試集。
2. 固定 `random_state=42`，使結果可重現。
3. 對 `State` 執行 One-Hot Encoding，並移除一個基準類別避免完全共線。
4. 對模型輸入執行 `StandardScaler`。
5. 將轉換後的欄位視為五個可選特徵：三個支出欄位與兩個州別虛擬變數。
6. 對每個 `K=1～5` 列舉特徵組合。

### 資料切分

| 資料集 | 筆數 | 比例 |
|---|---:|---:|
| 訓練集 | 40 | 80% |
| 測試集 | 10 | 20% |

特徵子集合的候選比較只使用訓練集進行 5-fold Cross Validation；選定每個 K 的組合後，再於固定測試集計算展示指標。

## 4. Modeling：模型建立

### 五種演算法

| 模型 | 目的 |
|---|---|
| Linear Regression | 作為無正則化的基準模型 |
| Ridge Regression | 使用 L2 正則化降低係數波動 |
| Lasso Regression | 使用 L1 正則化壓縮不重要係數 |
| Elastic Net Regression | 同時結合 L1 與 L2 正則化 |
| Huber Regression | 降低離群值對模型估計的影響 |

### 超參數設定

- Ridge 使用 `RidgeCV` 在對數尺度的 alpha 候選值中搜尋。
- Lasso 使用交叉驗證選擇 alpha。
- Elastic Net 使用交叉驗證選擇 alpha 與 `l1_ratio`。
- Huber 使用 `epsilon=1.35`、`alpha=0.0001`。

### K 特徵搜尋流程

每個模型各自執行以下步驟：

1. 對 `K=1～5` 建立所有可能的特徵組合。
2. 每個候選組合使用訓練集 5-fold KFold，並以 CV RMSE 評估。
3. 選出該 K 值下 CV RMSE 最低的組合。
4. 使用完整訓練集重新訓練該組合。
5. 在固定測試集計算 RMSE、MAE、R²、Adjusted R² 與 F-statistic。
6. 保存特徵名稱、係數、截距、方程式、預測值與殘差。

因此，演算法和 K 值形成雙層選擇：共可在儀表板查看 5 個模型 × 5 種特徵數量的結果。

## 5. Evaluation：模型評估

### 評估指標

| 指標 | 解讀 |
|---|---|
| MAE | 平均絕對誤差，越低越好 |
| RMSE | 對大誤差較敏感，越低越好 |
| R² | 模型解釋目標變異的比例，越高越好 |
| Adjusted R² | 對特徵數量加入懲罰，避免只因增加變數而提高分數 |
| F-statistic | 檢視整體線性模型的統計顯著性 |
| Residual | 實際值減預測值，用於觀察高估、低估與異常樣本 |

### 完整特徵模型結果

| 排名 | 模型 | MAE | RMSE | R² |
|---:|---|---:|---:|---:|
| 1 | Lasso 迴歸 | 6,419.67 | 7,967.65 | 0.9216 |
| 2 | Huber 穩健迴歸 | 6,873.35 | 8,530.55 | 0.9101 |
| 3 | 一般線性迴歸 | 6,961.48 | 9,055.96 | 0.8987 |
| 4 | Elastic Net 迴歸 | 7,049.26 | 9,077.85 | 0.8982 |
| 5 | Ridge 迴歸 | 7,070.00 | 9,082.68 | 0.8981 |

### Lasso 的 K 值示例

| K | 入選特徵摘要 | RMSE | R² |
|---:|---|---:|---:|
| 1 | 研發支出 | 7,833.02 | 0.9242 |
| 2 | 研發支出、行銷支出 | 7,843.02 | 0.9240 |
| 3 | 研發、行政、行銷支出 | 7,967.64 | 0.9216 |
| 4 | 研發、行銷、Florida、New York | 7,843.02 | 0.9240 |
| 5 | 完整特徵 | 7,967.64 | 0.9216 |

目前固定測試集上，Lasso 的 `K=1` RMSE 最低，顯示較簡單的模型在此切分下即可取得良好表現。然而，資料集只有 50 筆，不能據此斷言單一特徵在所有新資料上都一定最佳。

### 評估限制

- 測試集只有 10 筆，RMSE 與 R² 容易受個別樣本影響。
- 每個 K 的特徵組合透過訓練集 CV 選出，但儀表板的「最佳 K」仍是依固定測試集 RMSE 標示。
- 若用固定測試集反覆選模型或 K，可能產生選擇偏誤。
- F-statistic 以一般 OLS 形式計算，對正則化模型僅作探索性參考。
- 正式上線前應使用 Nested Cross Validation、獨立驗證集或更多外部資料重新確認。

## 6. Deployment：部署

### 部署形式

- `compare_models.py`：訓練、評估與輸出流程。
- `model_comparison_results.json`：完整模型與特徵進程資料。
- `linear_regression_feature_progression.png`：靜態分析圖。
- `startup-profit-dashboard/dist/`：不需後端的靜態互動式網站。

### 儀表板互動

- 切換五種演算法後，保留目前 K 值並載入該模型結果。
- 切換 `K=1～5` 後，更新指標、特徵、方程式、係數、預測與殘差。
- RMSE 與 R² 圖表重新繪製並高亮目前 K 值。
- 跨模型比較區會依目前 K 值重新排序。

### 更新流程

1. 更新 `50_Startups.csv`。
2. 執行 `python compare_models.py`。
3. 確認 JSON 與 PNG 已更新。
4. 使用本機 HTTP Server 驗證互動網站。
5. 提交程式、文件與產出至 GitHub。

### 後續改善

- 增加樣本數與外部驗證資料。
- 導入 Nested Cross Validation，將模型、超參數與 K 值選擇完整納入內層 CV。
- 增加信賴區間、殘差診斷與異常值報告。
- 建立自動化測試及 GitHub Actions，驗證資料產出與前端載入。
- 視需求部署至 GitHub Pages 或建立預測 API。
